Goal

Build on LCEL → memory/tools → LangGraph → Studio → Conventional Commits. One concept at a time. Add just enough engineering (tests, CI) to make the learning durable.

Where you are

  • Local Ollama + uv
  • Learning scripts + shared graph_core / Studio graph tutor
  • Soft/hard compression, pinned facts, checkpoint / thread mental model
  • Phase 1 graph: generate ↔ tools via tools_condition + ToolNode
  • Phase 2 HITL: interrupt() before tools; CLI / Studio resume; history lists checkpoint_id
  • Phase 3 streaming: CLI stream_mode=['updates','messages']; Studio streams via API
  • Phase 4 LangSmith: optional LANGSMITH_* in .env; CLI prints tracing status
  • Phase 5 tests: uv run pytest + GitHub Actions tests.yml
  • Phase 6: SessionFacts (Pydantic) + env memory budgets in settings
  • Light CI: Conventional Commits on PR and on push to main/dev

Detail for what you already know lives in study_notes.html. This page is the forward-looking plan.

Phases

1. Make the graph more agent-like (done on graph)

Engineering: graph_core now uses generate → tools_condition → tools (ToolNode) → generate. chatbot.py keeps hand-written run_turn for contrast. Compared with create_agent in compare_create_agent.py.

Concepts: conditional edges, ReAct loop, reducers / add_messages, create_agent.

2. Human-in-the-loop (HITL) (done on graph)

Engineering: tools node calls interrupt() before ToolNode; CLI asks y/N and resumes with Command(resume=…); Studio Interrupts panel. Type history in graph_chatbot.py to inspect checkpoint_id.

Concepts: HITL, interrupt / resume, checkpoint_id time travel.

3. Streaming (done on graph)

Engineering: graph_chatbot.py calls stream_with_hitl → graph.stream(..., stream_mode=['updates','messages']). Prints (stream: node=…) then tokenizes Bot: from the generate node. Studio already streams over the LangGraph API.

Concepts: stream modes, token vs graph events (and why string-streaming hid tool_calls before).

4. Observability (done — optional key)

Engineering: .env.example documents LANGSMITH_API_KEY / LANGSMITH_TRACING / LANGSMITH_PROJECT. settings.py loads them; CLI prints (langsmith: …); graph_server.py imports settings for Studio. Habit: open the run when debugging HITL/tool turns.

Concepts: LangSmith tracing, run vs thread, what Studio shows without a key.

5. Deeper engineering (done — smoke + CI)

Engineering: tests/test_smoke.py (helpers / graph nodes / LangSmith status — no Ollama). CI: .github/workflows/tests.yml runs uv sync --group dev + pytest on push/PR to main/dev. Ruff still optional later.

Concepts: test pyramid, CI beyond commitlint, dependency caching in Actions.

6. Config and quality (done)

Engineering: facts.SessionFacts validates harvested fields; regex still proposes values. settings owns OLLAMA_*, MAX_CONTEXT_TOKENS, SUMMARY_TRIGGER_TOKENS, LangSmith flags. Ruff remains optional.

Concepts: configuration management, structured validation beyond LLM output.

7. Separate themes (new repo)

Engineering: RAG / vector stores, FastAPI or Agent Chat UI, langgraph deploy.

Concepts: retrieval vs chat compression, Agent Server, production checkpointers (e.g. Postgres).

How to use this doc

  1. Pick one phase; implement on dev.
  2. When the concept sticks, move a short summary into study_notes.html.
  3. Open a PR if you want CI on the branch; merge to main only manually when you are ready.
  4. Keep Conventional Commits (feat:, docs:, ci:, …).

Definition of done (whole arc)

  • You can implement or clearly explain a conditional tool loop vs create_agent.
  • You can demo one HITL interrupt/resume.
  • CI runs at least one real test job (not only commit-message checks).
  • You know why RAG / production deploy belong in another project.
